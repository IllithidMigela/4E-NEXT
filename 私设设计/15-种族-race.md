# 种族（race）私设编辑器设计

> 优先级：**P1**（字段 + 威能引用）· 状态：**设计完成，待实现**
> 数据依据：`dist/data/categories/race.json`（官方 54 条）

## 一、卡片结构（右侧预览）

GenericCard 纯文本卡片：头部（名称/出处）+ gc-fields（属性奖励/体型/速度/视觉/技能）+ 风味 + 正文详情（外貌特征/态度和信仰 lore）。

官方正文骨架（实测词频）：

```
外貌特征 Physical Qualities       ×40   ← lore（折叠）
态度和信仰 Attitudes and Beliefs  ×23   ← lore（折叠）
（少量种族含「XX种族威能」机制节）        ← 机制（可展开）
```

## 二、数据模型

| 字段 | 类型 | 现状 |
| --- | --- | --- |
| name / nameEn / source | 基本信息 | ✅ |
| size 体型 / speed 速度 / vision 视觉 | select | ✅ |
| abilityOne / abilityTwo 属性奖励 | select | ✅ |
| skill 技能 | multichips | ✅ |
| sourceText 正文 | longtext | ✅（lore 为主） |

## 三、设计要点

1. **字段面板已就绪**（种族数据 core）：属性/体型/速度/视觉/技能——保持。
2. **候选排序增强**：官方属性组合频次统计（如 力量+体质 高频）→ 候选排序；速度取值收敛（6/7/8 等）→ select 候选收敛。
3. **种族威能引用（可选，低出现率）**：少数种族含「XX种族威能」机制节——复用威能引用编辑器，机制节展开 / lore 折叠（`splitThemeSections`）。低优先级，正文 textarea 已可承载。
4. 主次分明：基本信息 core；种族数据 core；外观/标签 附加设置。

## 四、解析方式

- 无新解析器主体；`splitThemeSections` 区分 lore（折叠）与机制节（展开）。
- 可选：种族威能节引用提取（与 theme 同函数）。

## 五、实现清单

- [ ] 属性组合/速度候选统计排序（小脚本 + 常量更新）
- [ ] （可选）种族威能引用编辑 + 章节折叠预览
