> 优先级：**P1**（复用强、离完成最近）· 状态：**设计完成，待实现**
> 关联代码：`homebrewSchema.ts`（字段/分区/序列化）、`EntryEditor.tsx`（表单）、`EntryCard.tsx` ItemCard（预览）、`styles.extra.css`

## 一、卡片结构（右侧预览 ItemCard）

```
┌─────────────────────────────────────────────┐
│ [图标] 名称 NameEn      [自制] 类别 · 稀有度 · L等级 │
│ 风味文本（独立结构化字段，卡片名字下）             │
│ 统计表（按格式族逐行对齐左侧面板）：              │
│   A：分类组 / 增强 / 价格 / 重量 / 重击           │
│   B：分类组 / 增强 / 价格 / 重量 / 甲类·AC        │
│   C：分类组 / 价格 / 重量（增强可选）              │
│   D：分类组 / 价格 / 重量                         │
│ 威能（专属区块，仅自制条目渲染）                   │
│ 特性（bg-item 段）·正文详情（details HTML）       │
└─────────────────────────────────────────────┘
```

**本重构要点（按威能标准）**：增强/重击/甲类 是**权威统计标量**，只出现在统计表（卡片左侧「统计数据」面板逐行对齐），不再写入 details 首行；details 纯派生（仅「类别：适合」+ 特性段 + 正文）。消除「标量 ↔ details」双重同步。

**现状差异**：官方装备的威能信息承载在 `details`（底部「正文详情」区块，`<div class="bold bg-item">威能…</div>` 结构）；自制条目走专属「威能」区块（`entry.power`）。两者渲染位置不同——结构化后统一走「威能」区块，官方格式双向对齐。

## 二、数据模型

### 2.0 装备格式四大类（2026-09-08 数据画像；2026-09-10 按 2603 条逐类审计勘误）

对 2603 条官方装备按「增强 → 重击 → 适合 → 威能段 → 特性段 → 段头族谱」结构轴聚类，得到四个格式族。各族决定**统计表行的构成**与**字段模板**，是各编辑面板分化的依据。

| 族 | 涵盖官方类别 | 特征 | 统计表行（相对差异） | 结构模板 |
| --- | --- | --- | --- | --- |
| **A · 进攻战斗件** | 武器·法器·机关附件 | 增强 100%＋重击 100%（机关附件 53%/20%）＋适合 100%，威能 ~80% | 分类组/增强/价格/重量/**重击** | 增强（攻击·伤害骰）→ 重击 → 特性(可选) → 威能段 |
| **B · 护甲（防御件）** | 护甲·盾牌 | 增强 100%（**值恒为「AC」**，官方无独立甲类/AC 行）、适合 100%，无重击，威能 67% | 分类组/增强/价格/重量 | 增强（→AC）→ 特性(可选) → 威能段 |
| **C · 通用魔法配件** | 奇物·头部·颈部·臂部·足部·手部·腰部·戒指·坐骑·伙伴·魔宠 | 无重击；主体「特性＋威能」；颈部附增强 100%；臂部/奇物适合 100%/40% | 分类组/价格/重量（增强可选）＋**适合行（臂部/奇物）** | 适合(可选) → 特性(可选) → 威能段 |
| **D · 消耗品/补给** | 消耗品·炼金物品·刺客毒药 | 无增强、几乎无特性；以「威能✦消耗」为主（炼金为「辅助威能✦消耗」），一次性 | 价格/重量 | 适合(可选) → 威能段（频率含「消耗」） |

**边界类**：
- 机关附件：增强 53%＋重击 20%＋威能 73%（战斗件与配件混合）→ **归 A 族**（`equipFamilyOf` 已改；原归 C 致重击行丢失）
- 弹药：增强 100%＋特性 100%＋威能 0% → C 模板 + 增强（已填值显隐），特性为主
- 另类奖励 / 龙晶强化：小众，泛化到 C 模板（适合候选开放：妖精魔法赠礼/元素赠礼…/（武器））

**「适合」（itemSuitable）**：官方 99% 魔法装备携带（details 首行 `{{!!item-category}}：{{!!item-suitable}}`）。武器/法器/护甲 的适合 token 与分类组同空间（重刃/法杖/鳞甲…）→ 用 `group` 承载并双向同步；其余类别按 `SUIT_CANDIDATES_BY_CATEGORY` 给候选与「适合」统计行（臂部=任意盾牌/轻盾/重盾/护腕，奇物=基地物品/纹身/异能小雕像…，消耗品=药剂及灵药/试剂/磨刀石，炼金=爆弹/油膏/药物，另类奖励=妖精魔法赠礼/元素赠礼…，龙晶强化=（武器））。

**威能段头族谱**（bg-item 段头基名，2603 条实测）：`威能` 2014 / `特性` 1443 / `辅助威能` 51 / `攻击威能` 20 / `固有增益` 11 / `神圣展现` 11 / `怪癖` 11——后三类为**非威能标题段**，编辑器以「自定义标题段」承载。

## 三、面板设计（主次分明）

`CATEGORY_SECTIONS.equipment` 已按卡片视觉从上到下重排：

| 面板 | core | 说明 |
| --- | --- | --- |
| 基本信息 · 装备 | ✅ | 名称/英文名/出处/形态/类别/稀有度/等级 |
| **风味文本** | ✅（新增） | 独立结构化字段，卡片名字下渲染（与威能一致） |
| 统计数据 | ✅ | 横排表（`equip-stats`）：分类组/增强/重击/适合/价格/重量，**按族分化**（见下）；增强控件附族目标提示（护甲→AC、武器/法器→攻击骰和伤害骰）；分类组/适合行带候选 chips |
| **物品特性** | ✅ | **官方「特性」段结构化编辑**（`ItemPropertySection`），段头「特性」+ 多行 `div.text`，多段可逐段添加 |
| **物品威能** | ✅（可选区块） | 74% 装备含威能；空内容收起为「＋ 添加」细条 |
| 正文 | ✅（可选区块，卡片正文详情） | 自由 Markdown 正文（官方残余头部行导入时落于此） |
| 外观 | — | 附加设置 |
| 标签 | — | 附加设置 |

**「统计数据」面板与卡片统计表按族分化**（由 `FAMILY_STAT_ROWS` 单一来源驱动，左面板显隐与右卡片行共用）：

| 字段 | A 武器/法器/机关附件 | B 护甲 | C 配件 | D 消耗品 |
| --- | --- | --- | --- | --- |
| 分类组 | ✅ | ✅ | — | — |
| 价格/重量 | ✅ | ✅ | ✅ | ✅ |
| 增强 | ✅ 攻击/伤害骰 | ✅（→AC） | 可选（颈部；已填值显隐） | — |
| 重击 | ✅（机关附件可选） | — | — | — |
| 适合 | —（=分类组） | —（=分类组） | ✅（臂部/奇物候选；有值显隐） | ✅（消耗品/炼金/另类候选） |

> 说明：**「分类组」仅对 A(武器/法器/机关附件)/B(护甲) 有意义**（`GROUPS_BY_CATEGORY` 也只定义这三类的候选）；魔宠/伙伴/坐骑等 C/D 通用配件与官方一致**无分类组**，不渲染该行。
> 类别切换（`itemCategory`）时自动切换统计表行模板，并清空不再适用的统计值（分类组 C/D 无、重击仅 A、增强 D 无、适合/增强对象随类别清空重推导）。

### 增强算法（2026-09-10：加值与对象两个正交量分离）

官方 details 的「增强：」行**永远是对象文本**（武器/法器/弹药=攻击骰和伤害骰、护甲=AC、颈部=强韧、反射和意志；加值数字从不出现，由物品等级推导）。旧版把对象文本塞进 `enh` 加值位，导致导入官方护甲后 `enh="AC"` 触发加值误告警。现拆为两个正交字段、各配算法、均可自主设定：

| 量 | 字段 | 算法（`enhBonusOf` / `enhTargetOf`） | 用户设定 |
| --- | --- | --- | --- |
| 增强加值（数值） | `enh` | 留空 = 按物品等级推导（`enhancementBonusForLevel`，多级并集如「2 7 12」→「+1/+2/+3」）；**清空输入框即跟随等级** | 输入框直接覆盖（如 +3），与推导不符时黄字提示 |
| 增强对象（文本） | `enhTarget` | 留空 = 类别默认（`ENH_TARGETS_BY_CATEGORY` 首项，2603 条增强行值分布实证） | 增强 chips（对象）+ 自定义输入；点当前项恢复默认 |

- `ENH_TARGETS_BY_CATEGORY` 键集合 = 「默认有增强的类别」（武器/法器/弹药/机关附件/护甲/盾牌/颈部）；奇物/头部/戒指等**不做加值推导**（与官方 0% 覆盖一致），但用户显式设置对象后即按等级推导加值。
- 机关附件对象混合（攻3/AC3/豁免2）→ 默认「攻击骰和伤害骰」，chips 三选。
- 官方脏数据规范化（`normalizeEnhTarget`）：剥前导 `+N` 加值与行尾句号（如「+5强韧、反射和意志。」→「强韧、反射和意志」）。
- 回填迁移（`draftToForm`）：官方增强行 → `enhTarget`；旧数据中与等级推导一致的加值 → 清空交还算法；曾被塞进 `enh` 的对象文本 → 归位 `enhTarget`。
- 卡片展示：增强行单元格 = `加值（对象）` 合并（如「+3（攻击骰和伤害骰）」/「+2（AC）」）。

## 四、物品威能结构化（核心新增）

### 4.1 官方格式（已实测）

```html
<div class="bold bg-item">威能（恐惧）✦每日（自由动作）</div>
<div class=text>触发：你使用此武器以诗人攻击威能命中一个敌人。<br>效果：…</div>
```

- 段头 = `威能（关键词）✦频率（动作）`，关键词可缺省（`威能✦每日（标准动作）`）
- 正文 = `<div class=text>` 行，多为纯文本，少数带内联 `<b>标签：</b>`（统计：特殊28 / 强化1 19 / 强化2 9 / 次要维持 1）

### 4.2 数据模型

```ts
interface ItemPowerSection {
  keywords?: string;                 // 威能（关键词）可缺省
  freq: "每日" | "遭遇" | "随意" | "消耗";  // 含装备专属「消耗」
  action: string;                    // 自由动作/次要动作/标准动作/即时中断/即时反应/无动作/移动动作
  blocks: PowerBlock[];              // 正文标签块（复用 20 标签 + 自由文本行）
}
```

### 4.3 编辑交互

- 「＋ 添加威能段」逐段添加（官方最多 4 段/件）
- 每段 = **段头行**（关键词 multichips 小候选 + 频率 chip + 动作 chip，官方风格顺序「✦频率（动作）」）+ **正文区**（复用 `PowerBlockEditor` 标签块）
- 频率候选：每日/遭遇/随意/消耗（`ITEM_FREQUENCIES`，区别于威能类的三值，多出「消耗」）
- 动作候选：官方 7 种 + 无动作

### 4.4 序列化 / 反序列化（官方格式双向对齐）

- `serializeItemPowerSections(sections)` → 官方 `<div class="bold bg-item">` 段头 + `<div class=text>` 行（内联标签输出 `<b>标签：</b>` 前缀；无标签纯文本直接输出）
- `parseItemPowerSections(html)` → 逆解析官方 HTML：按 `bg-item` 段头切段，段头解析 关键词/频率/动作，正文行解析内联标签
- `draftToForm` 补装备分支：导入官方条目时，把 details 里的 增强/重击/特性/威能段 逆解析回对应字段/段列表

### 4.5 预设系统（统计驱动，数据已产出现成）

| 预设名 | 结构 | 依据 |

### 官方数据审计勘误（2026-09-10，2603 条逐类实测，脚本 `web/_review_equip_audit.mjs`）

对官方全量装备按类别统计结构成分后，发现并修正六处设计与实现的偏差（含两处**数据损坏级**）：

1. **撤销「甲类/AC」**（数据损坏级·虚构字段）：官方护甲 295 条增强行值恒为「AC」，无任何独立甲类行。已删除 `armorClass` 字段、B 族统计行、回填与类型铺平；护甲防御 = 分类组（基础甲型）+ 增强（→AC）。
2. **补齐「适合」（itemSuitable）**（功能缺失级）：官方 99% 装备携带、ItemSlotPicker 槽位过滤依赖，此前完全无承载。新增字段 + `SUIT_CANDIDATES_BY_CATEGORY` 候选 + `suitRowFor` 统计行（非 A/B 类别）+ ItemCard 渲染；武器/法器/护甲 与分类组同 token 空间，`draftToForm` 双向映射、`buildEntry` 补写（自制条目与官方条目在槽位过滤下行为一致）。
3. **威能段头族谱**（数据损坏级·解析缺陷）：段头基名实测 7 种，原解析只认 `威能`——`辅助威能`51/`攻击威能`20 段的频率动作全丢（炼金物品 42 条几乎全中），`固有增益`11/`神圣展现`11/`怪癖`11 标题段整段变无头威能段。`ItemPowerSection` 增加 `base`（威能/辅助威能/攻击威能）与 `head`（自定义标题段）；解析跳过「特性」段（修复**特性内容被双重复解析**成伪「威能✦」段的伴生 bug）；编辑器加段头基名 chips + 自定义标题输入。
4. **威能正文序列化格式纠正**（数据损坏级）：原把威能卡的 `<table class=details>` 塞进 `div.text`，而解析只认行内 `<b>标签：</b>`——**已保存的私设装备重开会丢全部块结构**。改为官方行内格式（`<b>标签：</b>内容` 以 `<br>` 分行、行首 `&nbsp;` 表缩进），解析按行拆分并识别 毒药式 `<b>` / 普通式「标签：」/ 纯文本 三种行。
5. **残余头部行不丢**：炼金 42/42「配方花费/关键技能/时间」、机关附件 15/15「要求」、法器 12「前提」等未结构化行，原导入再保存即消失。新增 `residualEquipmentText`（剥除已结构化部分取残余）→ 正文；官方 sourceText 全为 `<<item-format>>` 宏占位（先清空），自制条目（origin=user）跳过防正文重复。
