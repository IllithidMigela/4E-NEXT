## 一、卡片结构（右侧预览）

GenericCard（gc-fields：职责/威能来源/关键技能）+ 正文；角色页另有完整职业能力面板解析（`ClassFeatureBlock`：`!! 职业特性` / `!!! N级：` 层级 / 威能授予 / 特性选择）。

官方正文骨架（实测词频，前 60 条样本）：

```
!! 职业特性                            ×31   ← 主体：!!! N级：小节（特性/威能授予）
!! 混职天赋选项                         ×31
!! 建议配搭                            ×25
!! 法器                               ×8
4级：属性值增加 Ability Score Increase  ×7    ← 等级特性

11级：典范之道特性 / 典范之道威能        ×7

14级：属性值增加                       ×7

```

## 三、设计要点（分两步）

### 第一步：章节树 + 等级特性（可先行交付）

1. **章节树编辑**：`!! 职业特性` 下的 `!!! N级：` 小节列表——等级前缀（1/2/3/4/6/8/10/11/12/16/18…）+ 标题 + 正文；复用 `LevelFeatureSections`（与典范/天命共用）。
2. **属性值增加槽位**：4/8/11/14/18 级 自动生成（官方固定规律），标题「N级：属性值增加」。
3. **固定分区**：混职天赋选项 / 建议配搭 / 法器——独立 textarea 分区（复用 theme lore 折叠）。

### 第二步：威能授予 + 特性选择（复杂，需角色页解析对齐）

4. **职业威能表**：等级 × 威能类型（随意/遭遇/每日/辅助）+ 威能引用——结构化列表，保存拼装 `!!! N级：` + `{{威能名}}`。
5. **特性选择标注**：识别「获得N个…威能」多选特性（角色页 `CLASS_CHOICE_INSTR` 识别逻辑成熟）——编辑端标注该小节为多选，提示选项来源。

## 四、解析方式

- `splitThemeSections`（已有）：!!/!!! 章节树。
- `extractClassPowers(sourceText)`：`!!! N级：` 小节内威能引用提取 → 威能表；保存反拼装。
- 属性值增加 / 典范之道特性 等固定标题识别 → 槽位。
